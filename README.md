# Transaction Ledger API

Node.js + Express + PostgreSQL. Accounts, credit/debit transactions, balance, paginated history, and a bonus money-transfer API.

## Setup

1. Install Node.js (LTS) and PostgreSQL.
2. Create a database named `ledger`.
3. Run `schema.sql` against it (pgAdmin Query Tool, or `psql -U postgres -d ledger -f schema.sql`).
4. Copy `.env.example` to `.env` and set your Postgres password in `DATABASE_URL`.
5. `npm install`
6. `npm start` -> http://localhost:3000

Health check: `GET /health`

## Error format (all errors)

```json
{ "error": { "code": "INSUFFICIENT_BALANCE", "message": "Insufficient balance for this debit" } }
```

| Status | Code | When |
|---|---|---|
| 400 | VALIDATION_ERROR | missing name / reference_id, bad fields |
| 400 | INVALID_TRANSACTION_TYPE | type is not credit/debit |
| 400 | INVALID_AMOUNT | amount <= 0, not a number, > 2 decimals |
| 400 | INVALID_ACCOUNT_ID | id is not a valid UUID |
| 400 | INVALID_PAGINATION | bad page/limit |
| 400 | INVALID_REQUEST_BODY | body is not valid JSON / not an object |
| 404 | ACCOUNT_NOT_FOUND | account does not exist |
| 405 | METHOD_NOT_ALLOWED | edit/delete of a transaction |
| 409 | DUPLICATE_TRANSACTION | same reference_id on same account (existing transaction in `error.details`) |
| 422 | INSUFFICIENT_BALANCE | debit larger than balance |
| 500 | INTERNAL_ERROR | unexpected error |

## API documentation

### 1. Create account
`POST /accounts`
```json
{ "name": "Alice" }
```
**201**
```json
{ "id": "uuid", "name": "Alice", "balance": "0.00", "created_at": "2026-10-27T10:00:00.000Z" }
```
A `balance` sent by the client is ignored; it always starts at 0.

### 2. Add transaction
`POST /accounts/:id/transactions`
```json
{ "type": "credit", "amount": 100, "description": "Salary", "reference_id": "ref-001" }
```
**201**
```json
{ "transaction": { "id": "...", "account_id": "...", "type": "credit", "amount": "100.00",
  "description": "Salary", "reference_id": "ref-001", "created_at": "..." }, "balance": "100.00" }
```
Errors: 400 (validation), 404 (account), 409 (duplicate reference_id), 422 (insufficient balance).

### 3. Get balance
`GET /accounts/:id/balance` -> **200** `{ "account_id": "uuid", "balance": "100.00" }`

### 4. Transaction history
`GET /accounts/:id/transactions?type=credit|debit&page=1&limit=10`

Latest first (`created_at DESC`). **200**
```json
{ "data": [ { "...transaction..." } ],
  "pagination": { "page": 1, "limit": 10, "total_records": 4, "total_pages": 1 } }
```
Defaults: page=1, limit=10. Max limit = 100.

### 5. Transfer (bonus)
`POST /transfers`
```json
{ "from_account_id": "uuid", "to_account_id": "uuid", "amount": 30, "description": "Rent" }
```
**201** returns `transfer_id`, and for `from` / `to` the new balance and the created transaction.
Errors: 400, 404 (either account missing), 422 (insufficient balance). On any failure nothing is saved.

## How data integrity is guaranteed

- **Atomicity:** balance update + transaction insert run inside one DB transaction (`withTransaction`); any error triggers ROLLBACK.
- **Concurrency:** the account row is locked with `SELECT ... FOR UPDATE`, so two simultaneous requests cannot overdraw an account. Transfers lock both rows in sorted-id order to avoid deadlocks.
- **Duplicates:** `UNIQUE (account_id, reference_id)` constraint plus an explicit check.
- **Money precision:** `NUMERIC(18,2)`, never floats. Debit uses `UPDATE ... WHERE balance >= amount`.
- **Constraints:** `CHECK (balance >= 0)`, `CHECK (amount > 0)`, `CHECK (type IN ('credit','debit'))`, foreign key on `account_id`.
- **Immutability:** no update/delete routes (they return 405) AND a database trigger blocks UPDATE/DELETE on `transactions`.

## Assumptions

- No authentication/authorization (not requested).
- Single currency; amounts have at most 2 decimal places.
- Balance and amounts are returned as strings (e.g. "100.00") to avoid floating-point errors.
- A duplicate `reference_id` returns **409** with the original transaction in `error.details`; balance is unchanged.
- Insufficient balance returns **422**.
- Transfers create one debit and one credit transaction with generated reference ids (`transfer:<id>:debit/credit`).
- Account ids are UUIDs generated by the database.
- Pagination: default page 1, default limit 10, max limit 100.
